# 渠道检测使用说明

## 入口与范围
主站导航“真实性检测”之后的“渠道检测”，路径 `/channel`。这是独立模块，旧 `/authenticity` 及其记录保持独立；没有巡检、配置保存或统计卡。

## 操作
1. 输入获授权的公网中转站地址与 API Key，选择实际传输协议。默认 OpenAI 兼容可检测三族模型；Claude / Gemini 原生仅适用于相应模型族。协议不是声称来源，不会自动换协议发付费重试。
2. 点击“验证连接并拉取模型”。区分鉴权失败、地址不可达、限流及上游故障；拉取清单不是官方型号认证。首次默认不选择模型，可逐项勾选或全选。
3. 点击“测试调参”，在弹窗按 Anthropic Claude、OpenAI、Google Gemini 分组，为每个模型设置声称来源。可统一设置当前族来源、单项修改、添加或删除模型。
4. 点击“开始立即检测”，弹窗关闭，主页显示实时进度。某个模型失败会记录并继续下一个。真实请求可能产生上游费用。
5. 在最近检测记录中按时间、地址搜索，查看证据详情或导出 CSV、JSON、MD。默认最近 7 天。导出包含地址和检测证据，应自行保护。

## 结论边界
- 来源一致：加权分 ≥75 且有效检查 ≥3 项。订阅 / 合作伙伴类来源（Claude Code + Max、Amazon Q / Kiro、AWS 合作伙伴）无法通过本 API 核验，即使满分也回落为证据不足。
- 疑似异常：存在偏离声称来源的检查，加权分处于 50–75 之间，不等于已证实造假。
- 来源不符：加权分低于 50，多项检查与声称来源不符。
- 证据不足：有效检查少于 3 项（含截断、拒绝、安全拦截），此时不给结论。传输错误单独记为检测失败，不作为伪造证据。
- 结论为概率判定；没有实现来源密码学认证，协议兼容、模型自报与签名字段存在均不足以单独证明来源。
- 分数是加权通过率（weight=0 的信息性信号只展示、不计分），不是渠道真实性概率。

## 数据与运行边界
Key 不写入配置或检测记录；浏览器离开页面清空连接状态，后台运行任务仍可能继续。服务端任务在内存中，重启不恢复未结束任务；已经落盘的记录保留。
记录默认位于 `web_data/channel/records.sqlite3`，可用 `Yhs-ApiDetect_CHANNEL_DIR` 调整目录，最多保留 5000 条。仅支持公网地址，拒绝本机、内网和重定向。公开部署前必须自行配置访问控制；记录接口不提供用户隔离。

## 离线验证

`python scripts/channel_browser_check.py`

浏览器脚本使用正式模板和模块脚本、模拟 API，不能替代真实上游及整站端到端验收；不需要真实密钥，不产生上游检测费用。
